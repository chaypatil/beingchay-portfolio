01/The problem

An AI can't match a candidate to a role it can't read.

“SDE-3, Platform” and “Sr. Backend Engineer (Go)” are close to the same job. “Staff SRE” and “Junior QA Automation” are nowhere near each other. Before the recruiter could match anyone, the model had to understand domain and seniority the way a good recruiter does. Engineering roles are the example here, the work covered more.

    02/The loop

    Five steps, run again and again until it was right.

    The model only got better because the data behind it got better. Every round tightened the labels, ruled on the edge cases and fed it back in.

    1. 01Data

      Pull in the roles

      Large sets of real job roles, the messy titles companies actually write.

    2. 02Human

      Tag every role

      Annotators label each one by domain and seniority against a shared rubric.

    3. 03Review

      Review and rule on edge cases

      Every label checked. Tricky cases decided once, written down as rules, reused.

    4. 04AI

      Fine-tune and test

      Reviewed data trains the model. Accuracy measured every round.

    5. 05AI

      Match candidates to roles

      The recruiter predicts who fits the roles clients need filled.

    6. 06Feedback

      Clients close the loop

      Beta feedback from clients came straight back into the labelling rules.
